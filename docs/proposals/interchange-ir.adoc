= Proposal: the Bowtie Interchange Model (BIM/1)
:toc:
:toclevels: 3

== Status

*Draft for decision, 2026-10-23.* Nothing in `src/` depends on this yet. The
schema is at
link:interchange/bim-1.schema.json[`docs/proposals/interchange/bim-1.schema.json`]
and a worked bowtie is at
link:interchange/example-bowtie.bim.json[`example-bowtie.bim.json`].
Companion proposals: link:import-export.adoc[import/export pipeline] and
link:ultraplan-diagramming.adoc[diagramming ultraplan].

== The problem this solves

`src/prototype/index.html` has exactly one interchange format: its own workspace
JSON. `backup()` writes it; `importBackup()` reads it through
`validateWorkspace()` and refuses anything else. That is a sound *storage*
format and a poor *interchange* format, for three reasons.

. *It is N×M.* Every new input (a spreadsheet register, a Visio drawing, an OCR
  scan of a workshop wall) needs its own reader and its own field-mapping code,
  and every new output needs its own writer. Two inputs and three outputs is six
  programs; ten of each is a hundred.
. *It is not a graph.* Threats, consequences and barriers are separate arrays
  joined by string ids in `barriers[].links` and `chainLinks[]`. An importer
  that produces a causal graph — the thing every external diagramming tool
  actually contains — has to invent a shape for it, and every importer invents a
  different one.
. *It has no room for provenance.* After an import, nothing records that a
  consequence came from row 17 of a spreadsheet, page 4 of a scanned PDF, or a
  fuzzy match the user accepted. The current importer appends `· imported` to
  the title and marks the decision for review. That is not traceability.

An intermediate representation fixes all three at once: adapters become N+M,
every tool maps onto one graph, and provenance is a field rather than a habit.

== Design principles

[cols="1,5",options="header"]
|===
| # | Principle

| P1 | *One canonical model, many profiles.* A profile is a named, versioned
  subset with extra constraints (`bowtie/workspace-v1`, `bowtie/flying-logic`).
  It is not a fork of the model.

| P2 | *Semantics and presentation are separate documents.* What a thing means
  round-trips; where it sits on a sheet does not have to. Layout lives in an
  overlay that can be discarded and recomputed.

| P3 | *Provenance is mandatory, not optional.* Every node and edge carries where
  it came from, by which method, with what confidence. A manual entry records
  `method: manual`, which is honest and cheap.

| P4 | *Loss is declared, not hidden.* An adapter that cannot represent a field
  lists it in `loss[]`. Silent loss is a defect; declared loss is a design
  decision the reader can audit.

| P5 | *Unknown is a value.* Missing likelihood is `null` with a reason, never
  zero. This mirrors the prototype's existing rule that unknown estimates cannot
  yield a within-appetite result.

| P6 | *Text is localisable by construction.* A user-visible string is a
  `LocalizedText` record with a required default and optional tagged
  translations — never a bare string that later needs a side table.

| P7 | *Canonical form is deterministic.* The same logical document serialises to
  the same bytes, so hashing, diffing, merging and CI fixtures are possible.

| P8 | *Identity survives transport.* Stable ids, source aliases, and an xref
  table mean a re-import updates rather than duplicates — and a merge can be
  explained afterwards.

| P9 | *Units are explicit.* A quantity without a unit is invalid. UCUM codes.
  No implicit conversion.

| P10 | *The past is a migration, not an if-statement.* Adding a field means
  registering a migration with a test, not scattering version checks through
  readers.

|===

== Layer model

[cols="1,2,3",options="header"]
|===
| Layer | Concern | Examples

| Transport
| bytes, encodings, containers
| `.xlsx` (zip + XML), `.docx`, PDF, PNG, SVG, `.drawio` (XML), `.vpp`,
  `.logic`, CSV bytes, charset detection

| Interchange (BIM/1)
| meaning
| nodes, edges, evidence, estimates, provenance, aliases

| Layout overlay
| position and style
| x/y, width/height, routing points, collapsed state, theme tokens

| Domain profile
| this application's rules
| appetite comparison, barrier verification state, learning closure

| Presentation
| rendering
| bowtie, causal chain, report, CSV, PDF, SVG, DOT
|===

A document therefore looks like:

[source,json]
----
{
  "ir": "bim/1",
  "document": { "id": "urn:uuid:0192f1...", "profiles": ["bowtie/workspace-v1"], "graphs": [ ... ] },
  "layout": { "graph-id": { "nodes": { ... }, "edges": { ... } } },
  "resources": [ { "id": "ev-1", "kind": "document", "uri": "...", "sha256": "..." } ],
  "provenance": { "adapter": "xlsx@1.2.0", "source": "...", "captured": "2026-10-23T09:00:00Z" }
}
----

== Core records

=== `Envelope`

[cols="1,1,3",options="header"]
|===
| Field | Type | Meaning

| `ir` | string, required | Always `bim/1`. The major version is in the value.
| `document` | `Document` | The payload.
| `layout` | map | Optional presentation overlay, keyed by graph id.
| `resources` | `Resource[]` | Evidence files by value (hash) or reference (URI).
| `provenance` | `Provenance` | How this document was produced as a whole.
| `extensions` | object | Vendor data that has no BIM meaning yet. Namespaced keys.
|===

=== `Document`

`id`, `created`, `modified`, `generator`, `profiles[]`, `locale`, `graphs[]`,
`policy`, `revisions[]`, `extensions`.

`policy` carries decisions and appetite: `appetiteStatement`, `capacity`,
`constraints`, `triggers`, `decision`. It is document-scoped because a decision
applies to a set of assessments, not one node.

`revisions` carries the review-checkpoint history (`history[]` in the current
schema), each with an id, timestamp, note, and a content hash of the snapshot.

=== `Graph`

`id`, `kind`, `title` (`LocalizedText`), `meta`, `nodes[]`, `edges[]`,
`groups[]`, `annotations[]`, `policy?`, `extensions`.

`kind` is an open string with a registered vocabulary:
`bowtie`, `causal`, `toc-crt`, `toc-frt`, `toc-prt`, `toc-trt`, `toc-ec`,
`toc-s&t`, `stpa`, `accimap`, `fault-tree`, `freeform`.

An unknown `kind` is *not* an error: it is a forward-compatible extension. A
strict reader that does not know the method must still preserve the graph and
may present it as freeform, stating that it did so.

=== `Node`

`id`, `kind`, `label` (`LocalizedText`), `text?` (`LocalizedText`, long form),
`fields` (typed by kind), `evidence[]`, `confidence?`, `tags[]`,
`provenance`, `extensions`.

`kind` vocabulary, by method family:

[cols="1,2,3",options="header"]
|===
| Family | Kinds | Notes

| Bowtie
| `hazard`, `top-event`, `threat`, `consequence`, `barrier`, `escalation`,
  `intermediate-event`, `opportunity`, `learning`
| `barrier` carries `side` (`prevention` \| `mitigation`), `status`, `standard`,
  `test`, `lastTest`, `due`, `critical`.
| Causal / TOC
| `objective`, `goal`, `critical-success-factor`, `necessary-condition`,
  `precondition`, `action`, `intermediate-effect`, `desirable-effect`,
  `undesirable-effect`, `obstacle`, `milestone`, `injection`, `solution`,
  `ude`
| Their names are Flying Logic's; keeping them exact makes import mechanical.
| Evidence
| `evidence`, `assumption`, `reservation`, `claim`
| `reservation` is the Category of Legitimate Reservation: clarity, existence,
  causality, insufficiency, additional cause, predicted effect.
| Governance
| `decision`, `person`, `organisation`, `control`, `obligation`
|
| Annotation
| `note`, `group`
| `group` is a container, not a semantic class; membership is a `contains` edge.
|===

`fields` is a map, validated per `kind` by a registry of small schemas. This
keeps the envelope stable while letting the method vocabulary grow. Suggested v1
fields for `barrier`: `side`, `status`, `owner`, `mechanism`, `standard`, `test`,
`lastTest`, `due`, `dependencies`, `sideEffects`, `critical`, and
`escalations[]` (escalation factors carried inline as `escalation` nodes plus
`weakens` edges, so the graph is the single source).

=== `Edge`

`id`, `kind`, `from`, `to`, `gate`, `condition` (`LocalizedText?`), `weight?`,
`lag?`, `confidence?`, `evidence[]`, `provenance`, `extensions`.

[cols="1,3",options="header"]
|===
| `kind` | Meaning

| `contributes`
| A contributes to B (bowtie threat → top event, top event → consequence).
| `requires`
| A is a necessary condition for B (TOC necessary-condition thinking).
| `inhibits`
| A prevents or reduces B (a barrier acting on a path).
| `shared-dependency`
| A and B fail together. Never treated as independent protection.
| `feedback`
| B feeds back into A after a delay. `lag` is required.
| `weakens`
| A degrades or defeats B (escalation factor → barrier).
| `same-as`
| Declares two nodes the same entity. Carries `score` and `method`.
| `linked-assessment`
| A consequence opens another bowtie.
| `contains`
| Group membership.
| `annotates`
| A note attached to a node or edge.
|===

`gate` is `none`, `and`, `or`, `xor`. `and` means every incoming edge is
required; `or` means any one is sufficient; `xor` means exactly one. These match
Flying Logic's Fuzzy AND/OR/XOR so that a round-trip does not reinterpret the
methodology.

`weight` is the edge strength, `-1.0` to `1.0`, where negative weights model
inhibition (Flying Logic's fuzzy NOT). Absent means `1.0`, not `0`.

=== Value types

[cols="1,2,3",options="header"]
|===
| Type | Shape | Rules

| `LocalizedText`
| `{ "default": "...", "translations": { "cy-GB": "..." }, "format": "text/plain" }`
| `default` required. Tags are BCP-47. `format` is `text/plain`,
  `text/asciidoc`, or `text/markdown`.
| `Quantity`
| `{ "value": 0.4, "unit": "1/a", "uncertainty": { "low": 0.2, "high": 0.7 } }`
| `unit` is a UCUM code and is never omitted. `uncertainty` is optional but, if
  present, must bracket `value`.
| `Instant`
| RFC 3339 with offset, or RFC 9557 when the time zone matters
| Never a bare local date for an event; a review date may be a `Date`.
| `Reference`
| `{ "uri": "...", "label": "..." , "sha256": "...", "retrieved": "..." }`
| `sha256` when the artefact is captured; `uri` alone when it can only be cited.
| `Confidence`
| `{ "scheme": "fuzzy" \| "probability" \| "ordinal", "value": 0.5, "basis": "..." }`
| The scheme travels with the number. A fuzzy 0.5 means indeterminacy, not a
  50% chance.
| `Provenance`
| see below
|
|===

`Provenance`:

[source,json]
----
{
  "adapter": "xlsx@1.2.0",
  "method": "declared" ,
  "source": { "name": "risk-register.xlsx", "sha256": "…" },
  "locator": { "sheet": "Bowties", "range": "A4:F19", "page": 4, "bbox": [72,110,540,690] },
  "captured": "2026-10-23T09:00:00Z",
  "confidence": 0.93,
  "review": { "state": "unreviewed", "reviewer": null, "at": null }
}
----

`method` is one of `declared` (the file said so), `inferred` (structure
detected), `ocr` (recognised from pixels), `suggested` (a heuristic or model
proposed it), `manual` (a person typed it). `review.state` is `unreviewed`,
`accepted`, `rejected`, `corrected`. The import UI must be able to filter on
both, which is what makes human-in-the-loop practical.

== Invariants

A validator is not a schema. The schema checks shape; these check meaning. Each
is a named rule so a failure can be reported and waived individually.

[cols="1,4,4",options="header"]
|===
| # | Rule | On violation

| I1 | Ids are unique within a document.
| Fatal.
| I2 | Every edge endpoint resolves to a node or group in the same graph.
| Fatal, unless the edge carries `provenance.review.state = rejected`.
| I3 | `gate` is `and`/`or`/`xor` only on edges that enter a node with more than
  one incoming edge; otherwise `none`.
| Warning; normalised to `none`.
| I4 | A `feedback` edge has `lag`.
| Error; the edge is preserved and flagged.
| I5 | A cycle contains at least one `feedback` edge or one declared waiver.
| Error; this is the prototype's existing `chainWarnings` rule, generalised.
| I6 | `barrier`-side relationships are edges (`inhibits`, `weakens`), not
  duplicated arrays inside `fields`.
| Fatal at write time; a reader may accept the legacy form and expand it.
| I7 | `status: verified` requires `owner`, `standard`, `test`, `lastTest`,
  `due`, and at least one evidence reference.
| Error; the node is downgraded to `incomplete`, with the reason recorded.
| I8 | An unknown estimate is `null`, never `0`.
| Fatal on write; a reader treats `0` as a real value only if `explicit: true`.
| I9 | Every quantity has a unit; conversions record their factor and source.
| Fatal.
| I10 | Every node and edge has `provenance`.
| Fatal on write; readers may synthesise one with `method: inferred` and say so.
| I11 | `LocalizedText.default` exists; every translation key is a valid BCP-47
  tag.
| Fatal.
| I12 | The semantic graph contains no geometry. Geometry lives in `layout`.
| Fatal on write; a reader moves it to the overlay and notes the migration.
| I13 | Canonical serialisation is a pure function of the logical document.
| Tested by fixture round-trip.
| I14 | A `same-as` merge never destroys the loser: it is retained with
  `mergedInto`, so the xref still explains itself.
| Fatal.
|===

== Identity, aliases, reconciliation

*Node ids* are opaque strings. Two origins are permitted:

. a UUIDv7 minted at first creation (time-ordered, collision-resistant), or
. `urn:bim:sha256:<hex>` derived from the canonical form of the node's
  identity-bearing fields, for sources that have no ids.

*Aliases* record what other systems call the same thing:

[source,json]
----
"aliases": [
  { "scheme": "xlsx:REG", "value": "REG-0042" },
  { "scheme": "drawio", "value": "cell-17" }
]
----

*Reconciliation* is a first-class stage, not an import side effect. When two
sources describe the same entity, the merge emits a `same-as` edge carrying the
score and method (`exact`, `normalised`, `agrep:k=2`, `manual`). The xref table
is kept even after merge, so "why is this one row of my register missing from the
model?" has an answer: it was merged into node X on this evidence.

This is also where the approximate-matching capability lands; see
link:import-export.adoc#agrep[the agrep section] of the pipeline proposal.

== Canonical form

. Normalise text to Unicode NFC.
. Normalise tags to lower-case BCP-47 with region where known.
. Serialise with JSON Canonicalization Scheme (RFC 8785): sorted keys, no
  insignificant whitespace, shortest round-trip numbers.
. Order arrays by declared key: nodes by `id`, edges by `(from, to, id)`,
  translations by tag.
. Omit absent optional fields; never emit `null` for "not supplied" except where
  `null` is itself the meaningful value (P5).
. Hash with SHA-256. The hash appears in `document.integrity` and in every
  checkpoint revision.

Two consequences: a golden-file test suite becomes possible, and a merge can ask
"has anything semantic changed?" rather than diffing whitespace.

== Versioning and migration

* The IR version is the major number in the `ir` value. A `bim/2` reader must
  refuse a `bim/1` document unless it ships the migration.
* Migrations live in `migrations/bim-1-to-2.*`, each a pure function with a
  fixture pair (`before.json`, `after.json`) and a stated behavioural change.
* Profiles version independently (`bowtie/workspace-v1`). A profile's version
  bump may tighten validation without changing the IR.
* `deprecated` fields stay readable for at least one major version and are
  reported by the reader with the migration that replaces them.

== Layout overlay

[source,json]
----
"layout": {
  "g-bowtie-1": {
    "version": 1,
    "nodes": { "n-1": { "x": 40, "y": 120, "w": 180, "h": 72, "collapsed": false } },
    "edges": { "e-1": { "routing": "orthogonal", "points": [[220,156],[300,156]] } },
    "groups": { "grp-1": { "x": 20, "y": 90, "w": 420, "h": 260, "collapsed": true } },
    "viewport": { "zoom": 1, "pan": [0, 0] },
    "theme": "default"
  }
}
----

The overlay is optional and lossy by design. A tool that imports our semantics
into its own auto-layout is not wrong; it is exercising P2. What must survive is
the *semantic* graph, plus enough of the overlay to make an external editor's
round-trip non-destructive when the external tool stores positions itself (Visio,
draw.io, Flying Logic all do).

== Projection onto today's workspace profile

The existing workspace JSON is a *profile*, not a competitor. Mapping:

[cols="2,3",options="header"]
|===
| Workspace field | BIM/1

| `workspace.schemaVersion`, `revision`
| `document.profiles` + `document.revision`
| `assessment` (one entry)
| one `graph` of kind `bowtie`, with `title`, `meta`, and `policy`
| `threats[]`, `consequences[]`, `events[]`, `barriers[]`, `opportunities[]`,
  `learning[]`
| `nodes[]` with the matching `kind`
| `barriers[].links[]`
| `inhibits` edges from the barrier to each referenced node
| `barriers[].escalations[]`
| `escalation` nodes + `weakens` edges
| `chainLinks[]`
| `edges[]` with `kind: contributes` (or `feedback` when `type: feedback`)
| `categories[]`, `likelihoodLabels[]`, `calibration`, `appetiteStatement`,
  `capacity`, `constraints`, `triggers`, `decision`
| `document.policy` + `graph.meta`
| `history[]`
| `document.revisions[]`
| `inherent`/`residual`/`target` estimates
| `fields.estimates` on the consequence node: `{ inherent, residual, target }`
|===

The mapping is total in both directions for every field the prototype currently
stores. That is the acceptance test for "lossless": a workspace export →
BIM → workspace import must produce a document that differs only in `id`,
`revision`, and timestamps, with all semantics identical.

== Serialisations

[cols="1,2,3",options="header"]
|===
| Encoding | Use | Notes

| Canonical JSON
| interchange, fixtures, hashing
| RFC 8785. `.bim.json` by convention.
| CBOR
| large documents, embedded
| Same logical model, deterministic map ordering.
| JSON-LD
| publication, linking to SKOS/OWL vocabularies
| Generated from the JSON; not hand-authored.
| CSV projection
| spreadsheets, review by non-users of the tool
| One row per node or edge, columns fixed by profile. Export-only.
| AsciiDoc projection
| printable report, review record
| Export-only; the prototype's printable report generalises.
| DOT / GraphML
| layout and analysis in graph tools
| Export; import supported for DOT (see the format matrix).
|===

== Conformance levels

[cols="1,2,4",options="header"]
|===
| Level | Name | Requirement

| L0 | Reader
| Produces a valid BIM/1 document from a source format. May be lossy, but must
  record every loss in `loss[]` and set `provenance.method` truthfully.
| L1 | Writer
| Emits a target format from BIM/1 without reading the source format.
| L2 | Round-trip
| `write(read(x))` is *semantically isomorphic* to `x` for the declared subset;
  a manifest lists what is not preserved. Tested with fixture pairs.
| L3 | Synchronising
| Preserves foreign identifiers and layout so an external edit can be merged
  back without duplicating entities. Required for Visio, draw.io, Flying Logic.
|===

Adapters declare their level. A file that cannot reach L2 must say so in the
import summary, in plain language, before the user commits.

We should reuse, not invent:

|===
| Standard | Use here

| BCP 47 / CLDR

| UCUM
| quantity units
| RFC 8785 (JCS)
| canonical JSON
| RFC 3339 / RFC 9557
| instants and time zones
| XLIFF 2.0
| translation round-trip for `LocalizedText`
| GraphML, DOT
| graph interchange and layout tooling
| XMI 2.5
| UML/ArchiMate/SysML export where a model tool is the consumer
| BPMN 2.0 XML
| process diagrams, if that notation is ever adopted
| OPML
| outline export (Flying Logic parity)
| MS Project XML / MPXJ
| plan export where a TOC tree becomes a schedule
| SHACL
| optional validation of the JSON-LD projection
|===

== What this does not solve

* It does not make lossless import possible from formats that do not carry the
  information. A PNG of a bowtie has no edges; OCR can recover text and some
  geometry, and the result must be labelled as inferred.
* It does not define a layout algorithm. It defines where layout goes.
* It does not make ids stable across systems that have no ids. Aliases and xrefs
  are the answer, and they require a human decision at least once.
* It does not replace the domain policy kernel. `src/core/policy.affine`
  evaluates appetite and learning closure; BIM carries the inputs and the
  recorded outcome, not the rules.

== Decisions requested

[cols="1,4",options="header"]
|===
| # | Decision

| D1 | Adopt BIM/1 as the interchange target for all adapters, with the workspace
  JSON retained as profile `bowtie/workspace-v1` (no forced migration of
  existing files).
| D2 | Keep layout out of the semantic document, in the overlay.
| D3 | Require provenance on every record, including manual entry.
| D4 | Use UUIDv7 for new ids and content hashes only where a source has no ids.
| D5 | Accept the named invariant list (I1–I14) as the validator contract, with
  per-rule waivers recorded in the document rather than in code.
| D6 | Approve the conformance levels as the basis for the adapter test kit.
|===

== Migration steps

. Freeze the current shape as a fixture pair (export, re-import, compare).
. Implement the reader and writer for the workspace profile only; prove L2.
. Add the validator with I1–I14 and a failing fixture for each rule.
. Move import/export behind the pipeline ports (see the pipeline proposal).
. Add the first non-JSON adapter (CSV), then the first diagram adapter (DOT).
. Only then add the second profile. One profile at a time, with its own kit.
